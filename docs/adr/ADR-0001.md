# ADR-0001 — Canonical trust lifecycle

**Status:** Accepted (implemented in `49e1788`)

**Context.** Two incompatible trust vocabularies existed: `trust.py`
(`VERIFIED/COMMUNITY_VALIDATED/UNVERIFIED`, uppercase) and `quality.py`
(`verified/unreviewed/flagged/invalidated/superseded`, lowercase).
Published results carried both a legacy `reproducibility.trust` and a
top-level `trust_state`. `export.py`'s legacy normalizer case-mismatched
every value and defaulted to `UNVERIFIED`, so the canonical dataset
surfaced trust incorrectly.

**Decision.** One canonical lowercase lifecycle:
`unreviewed → verified | community_validated → flagged → invalidated |
superseded`. The authoritative store is the top-level `trust_state` field;
`reproducibility.trust` is read-only legacy input. Legacy constant names
(`VERIFIED`, `COMMUNITY_VALIDATED`, `UNVERIFIED`) remain as aliases to the
canonical values for source compatibility. `effective_trust(doc)` is the
single resolution function.

**Consequences.** Existing results migrate deterministically; the
exported dataset now correctly reflects `verified`. No on-disk result
documents were rewritten — derived artifacts changed only where the old
code was wrong. Future lifecycle changes go through `trust.py`.
