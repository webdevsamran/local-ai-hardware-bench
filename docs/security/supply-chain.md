# Supply Chain

## Current measures

- **Zero runtime dependencies** — the CLI installs nothing beyond Python itself
- **Pinned Actions** — every GitHub Action is pinned to an immutable commit SHA
- **Least privilege** — workflows default to `contents: read`; write scopes granted per-job only
- **Dependabot** — weekly updates for GitHub Actions and pip dev dependencies
- **CodeQL** — security-extended static analysis on every PR and weekly
- **Release artifacts** — sdist + wheel + SHA256SUMS + CycloneDX SBOM attached to GitHub Releases
- **Build provenance attestation** — every released wheel and sdist carries a
  signed SLSA provenance statement, generated by
  `actions/attest-build-provenance` in the release workflow. It says which
  workflow, at which commit, on which runner produced the file — so a
  tampered artifact cannot claim to be ours

## Verification

```bash
sha256sum -c SHA256SUMS.txt   # the file is what we published

# ...and we published it, from this repository's release workflow
gh attestation verify aihwbench-<version>-py3-none-any.whl --repo webdevsamran/local-ai-hardware-bench
```

The checksum and the attestation answer different questions. A checksum proves
the bytes did not change in transit; it says nothing about where they came
from, and anyone can publish a checksum for anything. The attestation is the
part that ties the artifact to the workflow run that built it.
