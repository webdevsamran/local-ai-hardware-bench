# ADR-0005 — Measurement-source semantics (engine vs wall-clock)

**Status:** Accepted (implemented in `1f3599e`)

**Context.** llama.cpp treated SSE chunk counts as token counts; LM Studio
put a client wall-clock rate into the engine-counter field
`generation_tokens_per_second` despite its own docstring stating counter
tok/s is unavailable.

**Decision.** Metrics carry `metric_source` provenance:
`engine_counter` (runtime-reported usage/timing) vs
`client_wall_clock` (client-measured, never merged into engine counters)
vs `derived` (documented formula). Token-based metrics are populated only
from real token counters; transport chunk counts are separate fields with
an explicit non-token label.

**Consequences.** Readers can never confuse a wall-clock approximation with
an engine counter. Backends that cannot report counters keep those metrics
null, as documented.
